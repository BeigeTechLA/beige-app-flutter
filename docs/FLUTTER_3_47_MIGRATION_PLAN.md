## Ordering rationale
**Least impact first, ascending within every phase.** Flutter toolchain (Phase 1) up front per decision — it's the shared base. Then: 0-code minor bumps → 1-file → 2–3 file → 5–6 file → Stripe (13, native) → go_router (69) → Riverpod (177) → iOS 27 SDK. Each step leaves tree green so a regression bisects to one plugin. Riverpod 3 last among code work (largest surface); iOS 27 truly last (external Xcode dep).

## Risks
- **Riverpod 3 × 178 files** — dominant effort; may surface in test overrides too.
- **go_router 18** — redirect/ShellRoute API drift.
- **Plugin interaction** — Firebase + Stripe native min-version bumps can collide on iOS deploy target / Android Gradle.
- **Xcode 27** — external, not yet installed; blocks Phase 6 only.
