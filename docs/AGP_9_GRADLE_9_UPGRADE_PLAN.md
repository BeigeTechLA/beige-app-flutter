Worked on AGP 8 (looser lint-vital). Fix: `lint { checkReleaseBuilds = false }` — lint is static analysis only, does not touch the shipped binary.

C1/C2 from the risk table below (google-services / crashlytics-gradle) did **not** surface — those plugins built fine under AGP 9. No version bump needed there.

## Why this is low-risk (the key finding)

This is **not** a bleeding-edge jump. Flutter 3.47's own version checker (`flutter_tools/gradle/.../DependencyVersionChecker.kt`) already declares AGP 9.0.1 / Gradle 9.1.0 / Kotlin 2.3.20 as its **recommended** ("warn") targets. The project currently sits at the *oldest non-erroring* versions, so Flutter 3.47 is **already printing deprecation warnings** nudging toward exactly these versions. This upgrade silences all three.

| Dep | Flutter 3.47 `error` floor | Flutter 3.47 **`warn` target** | Current | After |
|-----|---------------------------|-------------------------------|---------|-------|
| Gradle | 8.14.0 | **9.1.0** | 8.14.3 ⚠️ below warn | 9.1.0 ✅ |
| AGP | 8.11.1 | **9.0.1** | 8.11.1 ⚠️ at error floor | 9.0.1 ✅ |
| Kotlin (KGP) | 2.2.20 | **2.3.20** | 2.3.10 ⚠️ below warn | 2.3.20 ✅ |
| JDK (build) | 17 | 17 | 21 ✅ | 21 ✅ |

AGP 9.0's own hard minimums (from [official release notes](https://developer.android.com/build/releases/agp-9-0-0-release-notes)) — all already satisfied except Gradle:

| AGP 9.0 needs | Min | Project | OK? |
|---------------|-----|---------|-----|
| Gradle | 9.1.0 | 8.14.3 | ❌ → the one real change |
| JDK | 17 | 21 | ✅ |
| Kotlin Gradle Plugin | 2.2.10 | 2.3.10 (→2.3.20) | ✅ |
| SDK Build Tools | 36.0.0 | 36 (Flutter-set) | ✅ |
| compileSdk | ≥35 | 36 (Flutter-set) | ✅ |
| NDK (default) | 28.2.13676358 | 28.2.13676358 (Flutter-set) | ✅ exact match |

**Net:** the only version actually below spec is Gradle. AGP/Kotlin bumps are "catch up to what Flutter already wants." JDK/SDK/NDK need zero change.

## Migration surface is clean

Scanned `android/**` for every AGP 9 breaking-change hotspot. **Zero hits** — no refactor needed:

- No `applicationVariants` / legacy variant API usage (removed in AGP 9).
- No `buildConfig` / `BuildConfig` references (off by default in AGP 9).
- No `aidl` / `renderscript` usage (off by default in AGP 9).
- `namespace` already set (`com.app.beige`) — required since AGP 8.
- Root `build.gradle.kts` is standard Flutter (build-dir redirect + subproject eval) — no deprecated DSL.

The two Flutter-migrator flags in `gradle.properties` are **intentionally left as-is** — Flutter's Gradle plugin owns them:
```properties
android.builtInKotlin=false   # Flutter manages Kotlin application; keep false
android.newDsl=false          # keep legacy DSL path Flutter expects
```
Do **not** flip these as part of this bump. They are Flutter-compat shims, not our knobs.
